Mock básico

O método page.route() permite interceptar uma requisição e usar route.fulfill() para fornecer uma resposta controlada pelo teste. 

await page.route('**/api/users', async route => {

await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify([
        {
            id: 1,
            name: 'João'
        }
    ])
});

});

Mock de objeto JSON

O teste pode criar um objeto JavaScript e transformá-lo em JSON para simular a resposta de uma API. 

const user = {
id: 1,
name: 'João',
email: 'joao@example.com'

};

await page.route('**/api/user', async route => {

await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify(user)
});

});

Mock de lista

Uma lista de objetos pode representar uma resposta contendo vários registros retornados pela API. 

const users = [
{
    id: 1,
    name: 'João'
},
{
    id: 2,
    name: 'Maria'
},
{
    id: 3,
    name: 'Carlos'
}

];

await page.route('**/api/users', async route => {

await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify(users)
});

});

Mock de login

O mock também pode simular respostas de autenticação, permitindo controlar o token e os dados do usuário retornados pela API. 

await page.route('**/api/login', async route => {

await route.fulfill({
    status: 200,
    contentType: 'application/json',

    body: JSON.stringify({
        token: 'abc123',

        user: {
            id: 1,
            name: 'João'
        }
    })
});

});

Simular erro 400

Respostas de validação podem ser simuladas para verificar como a interface reage quando a API rejeita uma operação. 

await page.route('**/api/login', async route => {

await route.fulfill({
    status: 400,
    contentType: 'application/json',

    body: JSON.stringify({
        error: 'Credenciais inválidas'
    })
});

});

Simular erro 500

Um erro 500 pode ser simulado para validar o comportamento da aplicação diante de uma falha inesperada no backend. 

await page.route('**/api/users', async route => {

await route.fulfill({
    status: 500,
    contentType: 'application/json',

    body: JSON.stringify({
        error: 'Erro interno do servidor'
    })
});

});

Simular lista vazia

Uma resposta vazia é útil para validar estados da interface como tabelas sem registros, mensagens informativas e estados de ausência de dados. 

await page.route('**/api/users', async route => {

await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify([])
});

});

Mock condicional

A resposta pode variar de acordo com a URL ou outros dados da requisição, permitindo criar diferentes cenários dentro da mesma rota. 

await page.route('**/api/users', async route => {

const url = route.request().url();

if (url.includes('empty=true')) {

    await route.fulfill({
        status: 200,
        contentType: 'application/json',
        body: JSON.stringify([])
    });

    return;
}

await route.fulfill({
    status: 200,
    contentType: 'application/json',

    body: JSON.stringify([
        {
            id: 1,
            name: 'João'
        }
    ])
});

});

Mock com headers

É possível adicionar headers à resposta mockada para reproduzir comportamentos específicos da aplicação. 

await page.route('**/api/users', async route => {

await route.fulfill({

    status: 200,

    headers: {
        'x-test': 'mocked'
    },

    contentType: 'application/json',

    body: JSON.stringify([
        {
            id: 1,
            name: 'João'
        }
    ])
});

});

Modificar resposta real

Quando apenas parte da resposta precisa ser alterada, route.fetch() permite obter a resposta real antes de modificá-la com route.fulfill(). 

await page.route('**/api/users', async route => {

const response =
    await route.fetch();

const json =
    await response.json();

json.users.push({
    id: 99,
    name: 'Usuário Mock'
});

await route.fulfill({
    response,
    json
});

});

Exemplo prático

Neste exemplo, a API de usuários é interceptada antes do carregamento da página. O teste fornece dados controlados e valida que eles aparecem na interface. 

test('exibir usuários mockados', async ({ page }) => {

await page.route('**/api/users', async route => {

    await route.fulfill({
        status: 200,
        contentType: 'application/json',

        body: JSON.stringify([
            {
                id: 1,
                name: 'João'
            },
            {
                id: 2,
                name: 'Maria'
            }
        ])
    });

});

await page.goto('https://example.com');

await page.getByRole('button', {
    name: 'Carregar usuários'
}).click();

await expect(
    page.getByText('João')
).toBeVisible();

await expect(
    page.getByText('Maria')
).toBeVisible();

});

Exemplo simulando erro

O mesmo mecanismo pode ser utilizado para validar mensagens de erro sem depender de uma falha real no backend. 

test('exibir erro da API', async ({ page }) => {

await page.route('**/api/users', async route => {

    await route.fulfill({
        status: 500,
        contentType: 'application/json',

        body: JSON.stringify({
            error: 'Erro interno do servidor'
        })
    });

});

await page.goto('https://example.com');

await page.getByRole('button', {
    name: 'Carregar usuários'
}).click();

await expect(
    page.getByText('Não foi possível carregar os usuários')
).toBeVisible();

});
QA Note

O mock permite controlar o cenário de teste. Você pode simular sucesso, erro, lista vazia, dados específicos e respostas inesperadas sem precisar alterar o backend. Para alterar apenas parte de uma resposta real, utilize route.fetch() e depois route.fulfill() com os dados modificados.
