Executar no modo debug

O parâmetro --debug inicia o teste com o Playwright Inspector, permitindo executar as ações passo a passo, inspecionar locators e acompanhar a execução no navegador. 

npx playwright test --debug

Depurar um arquivo específico

Quando a falha está concentrada em um arquivo, execute diretamente esse teste com --debug. 

npx playwright test tests/login.spec.ts --debug

Depurar a partir de uma linha

É possível indicar o arquivo e a linha onde o teste está definido para iniciar a investigação diretamente naquele ponto. 

npx playwright test tests/login.spec.ts:10 --debug

Depurar pelo nome do teste

O parâmetro -g ou --grep permite executar apenas os testes que correspondem ao padrão informado. 

npx playwright test -g "login" --debug

Executar com navegador visível

Por padrão, os testes são executados em modo headless. O parâmetro --headed permite visualizar a janela do navegador durante a execução. 

npx playwright test --headed

Utilizar o UI Mode

O --ui abre o UI Mode do Playwright, permitindo executar, acompanhar e investigar os testes de forma interativa. 

npx playwright test --ui

Pausar a execução

O método page.pause() cria um ponto de pausa durante a execução. Em modo debug, ele permite interromper o teste exatamente no ponto desejado. 

import { test } from '@playwright/test';

test(
'debug do formulário',
async ({ page }) => {

await page.goto(
    'https://example.com'
);

await page.pause();

await page.getByRole(
    'button',
    {
        name: 'Login'
    }
).click();

});

Playwright Inspector

O Playwright Inspector permite avançar passo a passo, visualizar a ação atual, editar locators e observar informações relacionadas à execução. 

npx playwright test --debug

Utilizar PWDEBUG

A variável de ambiente PWDEBUG=1 pode ser utilizada como alternativa para ativar o modo de debug com o Playwright Inspector. 

PWDEBUG=1 npx playwright test

Debug com Developer Tools

Com PWDEBUG=console, o Playwright disponibiliza o objeto playwright no console das Developer Tools do navegador. 

PWDEBUG=console npx playwright test

Inspecionar elemento pelo console

Durante o debug pelo console, o objeto playwright pode ser utilizado para consultar elementos e locators. 

playwright.$('button');

playwright.$$('button');

playwright.locator(
'button'
);

Inspecionar elemento

O método playwright.inspect() permite revelar um elemento diretamente no painel Elements das Developer Tools. 

playwright.inspect(
'text=Login'

);

Descobrir locator

O método playwright.selector() pode ser utilizado para obter um seletor a partir de um elemento selecionado nas Developer Tools. 

playwright.selector($0);

Gerar código automaticamente

O codegen abre o navegador e o Playwright Inspector para registrar as interações realizadas durante a exploração da aplicação. 

npx playwright codegen https://example.com

Codegen com navegador específico

O navegador utilizado pelo Codegen pode ser definido explicitamente através da opção --browser. 

npx playwright codegen \
--browser chromium \
https://example.com

Salvar código gerado

O código gerado pelo Codegen pode ser direcionado para um arquivo utilizando a opção --output. 

npx playwright codegen \
--output=generated.spec.ts \
https://example.com

Gravar Trace

O Trace registra informações da execução que podem ser analisadas posteriormente. Ele é especialmente útil para investigar falhas em ambientes como CI. 

npx playwright test --trace on

Abrir Trace Viewer

Depois de obter um arquivo de trace, o Trace Viewer permite navegar pelas ações, snapshots do DOM, screenshots, logs, requisições de rede e código-fonte. 

npx playwright show-trace trace.zip

HTML Reporter

O HTML Reporter apresenta os resultados dos testes e permite investigar testes que falharam, incluindo detalhes da execução e traces quando disponíveis. 

npx playwright show-report

Logs detalhados da API

A variável DEBUG=pw:api habilita logs detalhados das chamadas da API do Playwright, ajudando a entender o que acontece durante a execução. 

DEBUG=pw:api npx playwright test

Usar console.log

Logs próprios também podem ajudar a acompanhar valores e estados importantes durante a execução do teste. 

test(
'debug de dados',
async ({ page }) => {

await page.goto(
    'https://example.com'
);

const title =
    await page.title();

console.log(
    'Título:',
    title
);

});

Breakpoint no código

Uma pausa explícita pode ser colocada no ponto em que você deseja investigar o estado da aplicação. 

await page.goto(
'https://example.com'

);

await page.pause();

const title =
await page.title();

console.log(title);

Desacelerar o navegador

Ao utilizar a API de browser diretamente, a opção slowMo pode tornar as operações visualmente mais fáceis de acompanhar. 

import { chromium } from 'playwright';

const browser =
await chromium.launch({
headless: false,
slowMo: 100
});

const page =
await browser.newPage();

await page.goto(
'https://example.com'
);

Exemplo completo — investigando uma falha

O exemplo demonstra como inserir um ponto de pausa durante um teste para investigar o estado da página, validar o locator e continuar a execução depois da inspeção. 

import {
test,
expect

} from '@playwright/test';

test(
'investigar login',
async ({ page }) => {

// ==========================================
// ACESSAR APLICAÇÃO
// ==========================================

await page.goto(
    'https://example.com/login'
);

// ==========================================
// INSPECIONAR ESTADO
// ==========================================

await page.pause();

// ==========================================
// PREENCHER LOGIN
// ==========================================

await page.getByLabel(
    'Email'
).fill(
    'user@example.com'
);

await page.getByLabel(
    'Senha'
).fill(
    '123456'
);

// ==========================================
// EXECUTAR LOGIN
// ==========================================

await page.getByRole(
    'button',
    {
        name: 'Entrar'
    }
).click();

// ==========================================
// VALIDAR RESULTADO
// ==========================================

await expect(
    page.getByText('Dashboard')
).toBeVisible();

});

O debug deve ajudar a identificar a causa da falha, utilizando evidências da execução para validar a correção.

QA Note

O --debug inicia o Playwright Inspector e é uma das formas mais diretas de acompanhar um teste passo a passo. O --ui oferece uma experiência interativa para executar e investigar testes, incluindo recursos como locator picker e traces. O page.pause() é útil quando você já sabe exatamente em qual ponto deseja interromper a execução. O codegen ajuda a explorar a aplicação e gerar uma primeira versão dos locators e ações. Para falhas que precisam ser analisadas depois da execução, o Trace Viewer permite investigar ações, snapshots do DOM, screenshots, logs e requisições de rede. Para obter informações adicionais sobre as chamadas da API do Playwright, utilize DEBUG=pw:api. O fluxo recomendado é: REPRODUZIR → INSPECIONAR → COLETAR EVIDÊNCIAS → IDENTIFICAR CAUSA → CORRIGIR → VALIDAR.
