Rodar testes específicos

Playwright CLI / Test Selection

Executar um arquivo específico

Para executar somente um arquivo de teste, informe o caminho do arquivo após o comando playwright test. 

npx playwright test login.spec.ts

Executar um arquivo pelo caminho

Também é possível informar o caminho completo ou relativo até o arquivo de teste. 

npx playwright test tests/login.spec.ts

Executar um teste pelo nome

O parâmetro -g permite executar somente os testes cujo título corresponda ao padrão informado. 

npx playwright test -g "login"

Executar no Chromium

Utilize --project para selecionar um projeto específico configurado no Playwright. 

npx playwright test --project=chromium

Executar no Firefox 

npx playwright test --project=firefox

Executar no WebKit 

npx playwright test --project=webkit

Executar com apenas um worker

O parâmetro --workers=1 limita a execução a um único worker, sendo útil para investigar problemas relacionados a paralelismo ou ordem de execução. 

npx playwright test --workers=1

Repetir cada teste

O parâmetro --repeat-each permite executar cada teste várias vezes. 

npx playwright test --repeat-each=3

Utilizar o reporter em lista

O reporter list exibe os testes durante a execução em formato de lista. 

npx playwright test --reporter=list

Gerar relatório HTML

O reporter html gera um relatório visual com os resultados da execução. 

npx playwright test --reporter=html

Combinar opções

Os parâmetros podem ser combinados para criar uma execução mais específica. 

npx playwright test tests/login.spec.ts \


--project=chromium
--workers=1
--reporter=html

Executar um teste específico em debug

Combine a seleção do teste com --debug para investigar uma falha específica. 

npx playwright test tests/login.spec.ts --debug

Executar um teste específico com navegador visível 

npx playwright test tests/login.spec.ts --headed
QA Note

Durante a investigação de uma falha, evite executar toda a suíte desnecessariamente. Comece selecionando o arquivo ou teste com login.spec.ts ou -g. Se necessário, combine com --debug, --headed ou --workers=1 para tornar a investigação mais controlada.
