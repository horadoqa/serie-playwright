Executar um arquivo específico

Para executar somente um arquivo de teste, informe o caminho do arquivo após o comando playwright test. 

npx playwright test login.spec.ts

Executar um arquivo pelo caminho

É possível informar um caminho relativo até o arquivo de teste. Isso é especialmente útil quando os testes estão organizados em diferentes diretórios. 

npx playwright test tests/login.spec.ts

Executar múltiplos arquivos

Também é possível informar mais de um arquivo na mesma execução. 

npx playwright test \
tests/login.spec.ts \
tests/cadastro.spec.ts

Executar um teste pelo nome

O parâmetro -g, também disponível como --grep, permite selecionar testes cujo título corresponda ao padrão informado. 

npx playwright test -g "login"

Selecionar testes por padrão

O --grep utiliza um padrão para filtrar os títulos dos testes. Isso permite selecionar grupos de testes sem precisar informar cada arquivo manualmente. 

npx playwright test --grep "login"

Excluir testes por padrão

O parâmetro --grep-invert permite excluir da execução os testes que correspondem ao padrão informado. 

npx playwright test \
--grep-invert "skip"

Executar um projeto específico

O parâmetro --project seleciona um projeto definido na configuração do Playwright. Os projetos normalmente representam browsers ou diferentes ambientes de execução. 

npx playwright test \
--project=chromium

Executar no projeto Chromium 

npx playwright test \
--project=chromium

Executar no projeto Firefox 

npx playwright test \
--project=firefox

Executar no projeto WebKit 

npx playwright test \
--project=webkit

Combinar teste e projeto

Os filtros podem ser combinados para executar um teste específico dentro de um projeto específico. 

npx playwright test \
tests/login.spec.ts \
--project=chromium

Executar com um único worker

O parâmetro --workers=1 limita a execução a um único worker. Isso pode ser útil durante investigações relacionadas a paralelismo, compartilhamento de estado ou ordem de execução. 

npx playwright test \
--workers=1

Repetir cada teste

O parâmetro --repeat-each executa cada teste várias vezes. Pode ser utilizado para investigar comportamentos intermitentes. 

npx playwright test \
--repeat-each=3

Utilizar o reporter em lista

O reporter list exibe os testes durante a execução em formato de lista. 

npx playwright test \
--reporter=list

Utilizar o HTML Reporter

O reporter html gera um relatório visual com os resultados da execução. 

npx playwright test \
--reporter=html

Executar um teste específico em debug

A seleção do teste pode ser combinada com --debug para investigar uma falha específica utilizando o Playwright Inspector. 

npx playwright test \
tests/login.spec.ts \
--debug

Executar com navegador visível

O parâmetro --headed executa o teste exibindo a janela do navegador. 

npx playwright test \
tests/login.spec.ts \
--headed

Executar no UI Mode

O --ui abre a interface interativa do Playwright para executar e investigar os testes. 

npx playwright test \
tests/login.spec.ts \
--ui

Executar com Trace

O parâmetro --trace permite definir a estratégia de gravação do Trace durante a execução. 

npx playwright test \
tests/login.spec.ts \
--trace on

Combinar opções

Os parâmetros podem ser combinados para criar uma execução direcionada a um cenário específico. 

npx playwright test \
tests/login.spec.ts \
--project=chromium \
--workers=1 \
--trace on

Exemplo completo — investigação direcionada

Neste exemplo, a execução é direcionada para um arquivo específico, seleciona o projeto Chromium, utiliza um único worker e ativa o Trace para facilitar a investigação de uma possível falha. 

npx playwright test \
tests/login.spec.ts \
--project=chromium \
--workers=1 \
--trace on

Boas práticas

Durante a investigação de uma falha, reduza o escopo da execução sempre que possível. Comece pelo arquivo ou teste relacionado ao problema e adicione opções como projeto, worker, debug ou trace conforme a necessidade da investigação.

QA Note

Quando precisar investigar uma falha, evite executar toda a suíte sem necessidade. Comece selecionando o arquivo com tests/login.spec.ts ou filtrando testes pelo título com -g ou --grep. Quando existir um projeto específico, utilize --project para direcionar a execução. Para uma investigação mais controlada, combine a seleção do teste com --workers=1, --debug, --headed, --ui ou --trace. O objetivo é reduzir o escopo da execução, reproduzir o comportamento e coletar evidências suficientes para entender a falha. Fluxo: SELECIONAR → EXECUTAR → INVESTIGAR → COLETAR EVIDÊNCIAS → CORRIGIR → VALIDAR.
