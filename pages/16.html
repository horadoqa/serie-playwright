Cookies

Cookies são armazenados no BrowserContext e podem ser utilizados pela aplicação para manter informações de sessão, preferências ou outros dados enviados em requisições. 

await context.addCookies([
{
    name: 'session',
    value: 'abc123',
    domain: 'example.com',
    path: '/'
}

]);

Consultar cookies

O método context.cookies() retorna os cookies disponíveis no contexto atual. 

const cookies =
await context.cookies();

console.log(cookies);

Limpar cookies

O método clearCookies() remove os cookies armazenados no contexto. 

await context.clearCookies();

localStorage

O localStorage armazena dados associados à origem da aplicação. O Playwright possui uma API específica para manipular esse armazenamento. 

await page.goto(
'https://example.com'

);

await page.localStorage.setItem(
'token',
'abc123'
);

const token =
await page.localStorage.getItem(
'token'
);

console.log(token);

Consultar localStorage

Também é possível consultar todos os itens armazenados no localStorage. 

const items =
await page.localStorage.items();

console.log(items);

Limpar localStorage

O método clear() remove todos os itens do localStorage da origem atual. 

await page.localStorage.clear();

sessionStorage

O sessionStorage armazena dados associados à origem e à sessão da página. O Playwright possui uma API específica para manipular esse armazenamento. 

await page.goto(
'https://example.com'

);

await page.sessionStorage.setItem(
'user',
'João'
);

const user =
await page.sessionStorage.getItem(
'user'
);

console.log(user);

Storage State

O storageState() permite capturar o estado do contexto para reutilizá-lo posteriormente. O estado inclui cookies e armazenamento de origem, como localStorage. 

await page.context().storageState({
path: 'auth.json'

});

Storage State com IndexedDB

Quando a aplicação utiliza IndexedDB para armazenar informações relevantes para autenticação ou estado, é possível incluí-lo no snapshot utilizando indexedDB: true. 

await page.context().storageState({
path: 'auth.json',
indexedDB: true

});

Salvar estado após o login

Depois que o login for concluído, o estado autenticado pode ser salvo em um arquivo e reutilizado por outros testes. 

import { test, expect } from '@playwright/test';

test('autenticação', async ({ page }) => {

await page.goto(
    'https://example.com/login'
);

await page.getByLabel(
    'Email'
).fill(
    'user@example.com'
);

await page.getByLabel(
    'Senha'
).fill(
    '123456'
);

await page.getByRole(
    'button',
    {
        name: 'Entrar'
    }
).click();

await expect(
    page.getByText('Dashboard')
).toBeVisible();

await page.context().storageState({
    path: 'playwright/.auth/user.json'
});

});

Reutilizar estado

O arquivo de estado pode ser utilizado para iniciar um novo contexto já com os dados de autenticação previamente armazenados. 

test.use({
storageState:
    'playwright/.auth/user.json'

});

test(
'usuário autenticado',
async ({ page }) => {

await page.goto(
    'https://example.com/dashboard'
);

});

Configurar storageState

Quando vários testes utilizam o mesmo estado autenticado, o storageState pode ser configurado diretamente no playwright.config.ts. 

import {
defineConfig

} from '@playwright/test';

export default defineConfig({

use: {

    baseURL:
        'https://example.com',

    storageState:
        'playwright/.auth/user.json'

}

});

Setup de autenticação

Para projetos maiores, uma abordagem recomendada é utilizar um projeto de setup responsável por realizar a autenticação antes dos testes e gerar o arquivo de estado. 

import {
test as setup

} from '@playwright/test';

const authFile =
'playwright/.auth/user.json';

setup(
'autenticar usuário',
async ({ page }) => {

await page.goto(
    'https://example.com/login'
);

await page.getByLabel(
    'Email'
).fill(
    'user@example.com'
);

await page.getByLabel(
    'Senha'
).fill(
    '123456'
);

await page.getByRole(
    'button',
    {
        name: 'Entrar'
    }
).click();

await page.context().storageState({
    path: authFile
});

});

Persistir sessionStorage

Diferentemente de cookies e localStorage, o sessionStorage não é persistido automaticamente pelo storageState. Quando ele fizer parte da autenticação, é necessário salvá-lo e restaurá-lo explicitamente. 

const sessionStorage =
await page.evaluate(() =>
    JSON.stringify(sessionStorage)
);

console.log(sessionStorage);

Restaurar sessionStorage

O estado salvo pode ser injetado antes da aplicação executar utilizando addInitScript(). 

const storage =
JSON.parse(
    sessionStorageData
);

await context.addInitScript(
(storage) => {

    if (
        window.location.hostname ===
        'example.com'
    ) {

        for (
            const [key, value]
            of Object.entries(storage)
        ) {

            window.sessionStorage.setItem(
                key,
                value
            );

        }

    }

},
storage

);

Codegen

O codegen pode ser utilizado para explorar uma aplicação e gerar automaticamente interações que servem como ponto de partida para os testes. 

npx playwright codegen https://example.com

BrowserContext

Cada BrowserContext funciona como um ambiente isolado do navegador. Cookies e demais dados de estado pertencem ao contexto. 

import {
chromium

} from 'playwright';

const browser =
await chromium.launch();

const context =
await browser.newContext();

const page =
await context.newPage();

await page.goto(
'https://example.com'
);

await context.close();

await browser.close();

Criar contexto com estado

Um novo contexto pode ser criado já carregando um arquivo de estado previamente salvo. 

const context =
await browser.newContext({
    storageState:
        'playwright/.auth/user.json'
});

const page =
await context.newPage();

await page.goto(
'https://example.com/dashboard'
);

Múltiplos estados

É possível criar diferentes contextos utilizando arquivos de estado distintos. Isso é útil em cenários onde diferentes perfis precisam interagir na mesma execução. 

const adminContext =
await browser.newContext({
    storageState:
        'playwright/.auth/admin.json'
});

const userContext =
await browser.newContext({
storageState:
'playwright/.auth/user.json'
});

const adminPage =
await adminContext.newPage();

const userPage =
await userContext.newPage();

Exemplo completo — autenticação reutilizável

O exemplo abaixo demonstra o fluxo recomendado: autenticar, aguardar o estado da aplicação, salvar o estado e reutilizá-lo em um teste posterior. 

import {
test,
expect

} from '@playwright/test';

const authFile =
'playwright/.auth/user.json';

test.describe(
'Autenticação com Storage State',
() => {

test(
    'Salvar estado de autenticação',
    async ({ page }) => {

    // ==========================================
    // LOGIN
    // ==========================================

    await page.goto(
        'https://example.com/login'
    );

    await page.getByLabel(
        'Email'
    ).fill(
        'user@example.com'
    );

    await page.getByLabel(
        'Senha'
    ).fill(
        '123456'
    );

    await page.getByRole(
        'button',
        {
            name: 'Entrar'
        }
    ).click();

    // ==========================================
    // AGUARDAR APLICAÇÃO AUTENTICADA
    // ==========================================

    await page.waitForURL(
        '**/dashboard'
    );

    await expect(
        page.getByText('Dashboard')
    ).toBeVisible();

    // ==========================================
    // SALVAR ESTADO
    // ==========================================

    await page.context().storageState({
        path: authFile
    });

});


test(
    'Reutilizar estado',
    async ({ browser }) => {

    // ==========================================
    // CRIAR CONTEXTO AUTENTICADO
    // ==========================================

    const context =
        await browser.newContext({
            storageState: authFile
        });

    const page =
        await context.newPage();

    // ==========================================
    // ACESSAR ÁREA PROTEGIDA
    // ==========================================

    await page.goto(
        'https://example.com/dashboard'
    );

    // ==========================================
    // VALIDAR AUTENTICAÇÃO
    // ==========================================

    await expect(
        page.getByText('Dashboard')
    ).toBeVisible();

    await context.close();

});

});

QA Note

O BrowserContext mantém o estado isolado de uma sessão do navegador. Cookies podem ser adicionados, consultados e removidos diretamente pelo contexto. O localStorage e o sessionStorage possuem APIs próprias no Playwright atual. O storageState é a principal estratégia para salvar e reutilizar o estado autenticado. Cookies e localStorage fazem parte do estado persistido. IndexedDB, OPFS e credenciais WebAuthn podem ser incluídos quando suas respectivas opções são habilitadas. O sessionStorage possui um tratamento diferente e não é persistido automaticamente pelo storageState. Quando sessionStorage fizer parte da autenticação, salve e restaure esse estado explicitamente. Para projetos maiores, prefira uma rotina de autenticação dedicada e armazene os arquivos de estado em playwright/.auth. Nunca versione arquivos de autenticação que contenham cookies, tokens ou outras informações sensíveis. O fluxo principal é: LOGIN → SALVAR ESTADO → REUTILIZAR → TESTAR.
