GET — consultar dados

O método GET é utilizado para consultar recursos disponíveis na API. 

import { test, expect } from '@playwright/test';

test('consultar usuários', async ({ request }) => {
  const response = await request.get('https://serverest.dev/usuarios');

  expect(response.ok()).toBeTruthy();

  expect(response.status()).toBe(200);

  // Verificando o tipo de conteúdo da resposta é um JSON

  const data = await response.json();
  
  expect(Array.isArray(data.usuarios)).toBeTruthy();
  
  // console.log(data);
});

Validar status da resposta

O status HTTP indica o resultado da operação realizada pela API. A validação do status deve fazer parte das assertions do teste. 

const response = await request.get('https://serverest.dev/usuarios');

expect(response.status()).toBe(200);

expect(response.ok()).toBeTruthy();

Ler resposta JSON

Utilize response.json() para transformar o corpo da resposta JSON em um objeto JavaScript. 

const response = await request.get('https://serverest.dev/usuarios');

const data = await response.json();

expect(Array.isArray(data.usuarios)).toBeTruthy();

POST — criar recurso

O método POST normalmente é utilizado para criar um novo recurso. 


const cadastroResponse = await request.post('https://serverest.dev/usuarios',
    {
        data: {
          nome: 'Hora do QA',
          email: 'horadoqa@exemple.com',
          password: '1q2w3e4r',
          administrador: 'true'
        }
      }
);

expect(cadastroResponse.status()).toBe(201);

PUT — atualizar recurso

O método PUT pode ser utilizado para atualizar os dados de um recurso existente. 


const updateResponse = await request.put(
      `https://serverest.dev/usuarios/${userId}`,
      {
        headers: {
          accept: 'application/json',
          'Content-Type': 'application/json'
        },
        data: {
          nome: 'Hora do QA - Atualizado',
          email: email,
          password: '1q2w3e4r',
          administrador: 'true'
        }
      }
    );

expect(updateResponse.status()).toBe(200);

PATCH — atualização parcial

O método PATCH é utilizado quando apenas parte dos dados de um recurso precisa ser alterada. 

const response =
await request.patch('/api/users/1', {

    data: {
        name: 'Novo nome'
    }

});

expect(
response.ok()
).toBeTruthy();

DELETE — remover recurso

O método DELETE é utilizado para remover um recurso da API. 

const response =
await request.delete('/api/users/1');

expect(
response.ok()
).toBeTruthy();

Query parameters

Parâmetros de consulta podem ser enviados utilizando a propriedade params. 

const response =
await request.get('/api/users', {

    params: {
        page: 1,
        limit: 10
    }

});

expect(
response.ok()
).toBeTruthy();

Headers

Headers podem transportar informações como autenticação, tipo de conteúdo e outras informações necessárias para a comunicação com a API. 

const response =
await request.get('/api/users', {

    headers: {
        'Authorization': 'Bearer abc123',
        'Accept': 'application/json'
    }

});

expect(
response.ok()
).toBeTruthy();

Enviar JSON

A propriedade data permite enviar dados no corpo da requisição. O Playwright serializa o objeto para JSON quando apropriado. 

const response =
await request.post('/api/users', {

    data: {
        name: 'Maria',
        email: 'maria@example.com'
    }

});

const data =
await response.json();

expect(
data.name
).toBe('Maria');

Ler resposta como texto

Quando a API não retorna JSON, utilize response.text() para acessar o conteúdo da resposta como texto. 

const response =
await request.get('/api/message');

const body =
await response.text();

expect(
body
).toContain('Sucesso');

Validar headers da resposta

Os headers da resposta também podem ser validados para verificar informações retornadas pelo servidor. 

const response =
await request.get('/api/users');

const headers =
response.headers();

expect(
headers['content-type']
).toContain('application/json');

Autenticação

Um fluxo comum de API é realizar login, receber um token e utilizar esse token nas chamadas protegidas. 

const response =
await request.post('/api/login', {

    data: {
        email: 'user@example.com',
        password: '123456'
    }

});

expect(
response.ok()
).toBeTruthy();

const data =
await response.json();

expect(
data.token
).toBeDefined();

APIRequestContext

Também é possível criar um contexto específico para testes de API utilizando request.newContext(). Isso permite configurar uma baseURL e outras opções para as requisições. 

import {
test,
expect,
request

} from '@playwright/test';

test('API', async () => {

const apiContext =
    await request.newContext({
        baseURL: 'https://example.com'
    });

const response =
    await apiContext.get('/api/users');

expect(
    response.ok()
).toBeTruthy();

await apiContext.dispose();

});

API real — ServeRest

Para um cenário mais próximo de um teste real, podemos utilizar a API pública do ServeRest. O exemplo abaixo trabalha diretamente com usuários e utiliza os endpoints de cadastro, login, consulta, atualização e exclusão. 

Base URL

https://serverest.dev

POST /login
GET /usuarios/:id
PUT /usuarios/:id

Exemplo completo — CRUD

Neste exemplo, o teste executa um fluxo completo de API: cria um usuário, realiza login, consulta o registro, atualiza seus dados e finalmente exclui o usuário. O userId é obtido dinamicamente durante o cadastro e o token retornado pelo login é utilizado nas operações protegidas. 

import { test, expect } from '@playwright/test';

test.describe('CRUD - Usuário ServeRest', () => {

test(
    'Create → Login → Read → Update → Delete',
    async ({ request }) => {

    // ==========================================
    // CREATE - Cadastrando usuário
    // ==========================================

    const email =
        `horadoqa${Date.now()}@example.com`;

    const cadastroResponse =
        await request.post(
            'https://serverest.dev/usuarios',
            {
                data: {
                    nome: 'Hora do QA',
                    email,
                    password: '1q2w3e4r',
                    administrador: 'true'
                }
            }
        );

    expect(
        cadastroResponse.status()
    ).toBe(201);

    const cadastroBody =
        await cadastroResponse.json();

    expect(
        cadastroBody
    ).toEqual(
        expect.objectContaining({
            message:
                'Cadastro realizado com sucesso',

            _id:
                expect.any(String)
        })
    );

    const userId =
        cadastroBody._id;

    console.log(
        'CREATE: Usuário criado com sucesso'
    );

    // ==========================================
    // LOGIN - Realizando login
    // ==========================================

    const loginResponse =
        await request.post(
            'https://serverest.dev/login',
            {
                data: {
                    email,
                    password: '1q2w3e4r'
                }
            }
        );

    expect(
        loginResponse.status()
    ).toBe(200);

    const loginBody =
        await loginResponse.json();

    expect(
        loginBody
    ).toEqual(
        expect.objectContaining({
            message:
                'Login realizado com sucesso',

            authorization:
                expect.stringContaining('Bearer ')
        })
    );

    const token =
        loginBody.authorization;

    console.log(
        'LOGIN: Login realizado com sucesso'
    );

    // ==========================================
    // READ - Consultando usuário
    // ==========================================

    const readResponse =
        await request.get(
            `https://serverest.dev/usuarios/${userId}`,
            {
                headers: {
                    Authorization: token
                }
            }
        );

    expect(
        readResponse.status()
    ).toBe(200);

    const readBody =
        await readResponse.json();

    expect(
        readBody
    ).toEqual(
        expect.objectContaining({
            _id: userId,
            nome: 'Hora do QA',
            email,
            administrador: 'true'
        })
    );

    console.log(
        'READ: Usuário consultado com sucesso'
    );

    // ==========================================
    // UPDATE - Atualizando usuário
    // ==========================================

    const updateResponse =
        await request.put(
            `https://serverest.dev/usuarios/${userId}`,
            {
                headers: {
                    Authorization: token
                },

                data: {
                    nome:
                        'Hora do QA - Atualizado',

                    email,

                    password:
                        '1q2w3e4r',

                    administrador:
                        'true'
                }
            }
        );

    expect(
        updateResponse.status()
    ).toBe(200);

    const updateBody =
        await updateResponse.json();

    expect(
        updateBody.message
    ).toBe(
        'Registro alterado com sucesso'
    );

    console.log(
        'UPDATE: Usuário atualizado com sucesso'
    );

    // ==========================================
    // DELETE - Excluindo usuário
    // ==========================================

    const deleteResponse =
        await request.delete(
            `https://serverest.dev/usuarios/${userId}`,
            {
                headers: {
                    Authorization: token
                }
            }
        );

    expect(
        deleteResponse.status()
    ).toBe(200);

    const deleteBody =
        await deleteResponse.json();

    expect(
        deleteBody.message
    ).toBe(
        'Registro excluído com sucesso'
    );

    console.log(
        'DELETE: Usuário excluído com sucesso'
    );

});

});

QA Note

O objeto request permite testar APIs sem precisar abrir uma página no navegador. Utilize GET para consultas, POST para criação, PUT/PATCH para atualizações e DELETE para remoção. Em fluxos autenticados, capture o token retornado pelo login e utilize-o no header Authorization das chamadas protegidas. No exemplo com o ServeRest, o teste utiliza um e-mail único baseado em Date.now(), evitando colisões com usuários criados em execuções anteriores. O fluxo completo executa: CREATE → LOGIN → READ → UPDATE → DELETE. Valide não apenas o status HTTP, mas também o corpo da resposta, headers, mensagens, identificadores e os dados retornados pela API.
