Configuração básica

O arquivo playwright.config.ts centraliza configurações compartilhadas utilizadas durante a execução dos testes. 

import { defineConfig } from '@playwright/test';

export default defineConfig({

testDir: './tests',

use: {
baseURL: 'https://example.com',
headless: true,
screenshot: 'only-on-failure',
video: 'retain-on-failure',
trace: 'on-first-retry'
},

retries: 2,

workers: 4,

reporter: 'html'

});

Diretório dos testes

A propriedade testDir define o diretório onde o Playwright deve procurar os arquivos de teste. 

export default defineConfig({

testDir: './tests'

});

URL base

A propriedade baseURL permite utilizar caminhos relativos nos testes, evitando repetir a URL completa da aplicação. 

use: {

baseURL: 'https://example.com'

}

Com essa configuração, os testes podem utilizar: 

await page.goto('/login');

await page.goto('/dashboard');

Headless

A propriedade headless controla se o navegador será executado com ou sem interface visual. 

use: {

headless: true

}

Screenshots

A configuração screenshot determina quando screenshots devem ser capturados durante a execução. 

use: {

screenshot: 'only-on-failure'

}

Também é possível capturar screenshots sempre: 

use: {

screenshot: 'on'

}

Gravação de vídeo

A propriedade video controla a gravação dos testes e pode ser utilizada para preservar evidências de execuções com falha. 

use: {

video: 'retain-on-failure'

}

Trace

O Trace registra informações detalhadas da execução, permitindo investigar posteriormente ações, snapshots, screenshots e informações relacionadas à execução. 

use: {

trace: 'on-first-retry'

}

Retries

A propriedade retries define quantas vezes um teste que falhou pode ser repetido. 

retries: 2

Workers

A propriedade workers controla a quantidade de workers utilizados para executar os testes em paralelo. 

workers: 4

Reporter

O reporter define como os resultados dos testes serão apresentados ou armazenados. 

reporter: 'html'

Configurar múltiplos projetos

A propriedade projects permite configurar diferentes browsers, dispositivos ou ambientes dentro da mesma suíte. 

import {

defineConfig,
devices
} from '@playwright/test';

export default defineConfig({

projects: [

{
  name: 'chromium',

  use: {
    ...devices['Desktop Chrome']
  }
},

{
  name: 'firefox',

  use: {
    ...devices['Desktop Firefox']
  }
},

{
  name: 'webkit',

  use: {
    ...devices['Desktop Safari']
  }
}

]

});

Timeout global

A propriedade timeout define o tempo máximo permitido para a execução de cada teste. 

timeout: 30 * 1000

Timeout das assertions

A configuração expect.timeout define o tempo máximo de espera das assertions. 

expect: {

timeout: 5000

}

Boas práticas

Centralize configurações compartilhadas no arquivo de configuração e utilize projetos quando houver diferentes browsers, dispositivos ou ambientes. Evite duplicar configurações diretamente nos testes quando elas puderem ser definidas globalmente.

QA Note

O playwright.config.ts funciona como o ponto central de configuração da suíte. Utilize testDir para organizar a descoberta dos testes, use para configurações compartilhadas do navegador, projects para diferentes ambientes ou browsers, e propriedades como timeout, retries e workers para controlar a execução. Para investigação de falhas, configure também screenshot, video e trace como mecanismos de coleta de evidências. O objetivo é manter a configuração centralizada, previsível e reutilizável entre os testes. Fluxo: CONFIGURAR → EXECUTAR → COLETAR EVIDÊNCIAS → REPORTAR → ANALISAR.
